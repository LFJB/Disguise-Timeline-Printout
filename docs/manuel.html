Disguise Timeline Printout v1.0 · plugin Designer + CLI · Lightfield

Timeline → papier
le manuel

Un plugin pour Disguise Designer qui lit la timeline du projet ouvert (pistes, sections, cues, layers et leurs paramètres) et en fait un rapport imprimable, sur papier ou en PDF. Pour documenter un show et pouvoir le reprendre. Un petit outil en ligne de commande Python fait la même chose depuis une autre machine.

Vue d'ensemble

Le plugin envoie un petit script Python à Designer par son API REST locale (POST /api/session/python/execute). Ce script parcourt la timeline et renvoie les données en JSON. Le plugin les affiche, puis construit le rapport et ouvre la boîte d'impression.

Le plugin (le plus simple)

Un dossier à déposer dans le projet Designer. Tout se passe dans un panneau de Designer, sans rien installer d'autre.

La ligne de commande (optionnelle)

Des scripts Python 3 qui interrogent Designer depuis une autre machine du réseau, enregistrent les données en JSON et écrivent un rapport HTML.

01

Installer le plugin

Il faut Disguise Designer r32 ou plus récent. Le zip de la release contient le dossier timeline-printout-plugin/ (le plugin), les fichiers de la ligne de commande, ce manuel et un LISEZMOI.txt.

  1. Copier le dossier du plugin dans le projetLe dossier timeline-printout-plugin/ entier va dans le dossier plugins/ du projet Designer : 
    <projet>/plugins/timeline-printout-plugin/
  d3plugin.json
  index.html
  icon.svg
  2. Activer l'Application ModeManager › Machine Settings › Enable Application Mode. Sans lui, la boîte d'impression ne s'ouvre pas.
  3. Ouvrir ou relancer le projetLe plugin Timeline Printout apparaît dans le Plugin Launcher.
Le plugin a besoin d'une session Designer ouverte (requiresSession) : il lit le projet en cours.
02

Utiliser le plugin

  1. Ouvrir le pluginDans le Plugin Launcher de Designer, Timeline Printout.
  2. Include paramsCochée par défaut : chaque layer est lu avec ses paramètres. Décochée : seuls le module, les temps et le média sont lus.
  3. ExtractLe plugin lit la liste des pistes, puis les extrait une par une (la barre d'état affiche « Extraction piste 2 / 5… »). À la fin : nombre de pistes, de layers et de cues, et les avertissements éventuels.
  4. ParcourirUne rubrique par piste (clic sur l'en-tête = replier / déplier), une ligne par section avec son timecode, sa note, ses tags et son crossfade, puis une carte par layer actif.
  5. Choisir les pistesLa case à gauche du nom de chaque piste : décochée, la piste est grisée et ne sera pas imprimée. Toutes sont cochées après chaque Extract.
  6. Print / PDFLe rapport s'affiche dans le panneau et la boîte d'impression s'ouvre tout de suite : imprimer, ou enregistrer en PDF. ← Back revient à l'aperçu.
Extraire piste par piste évite que Designer coupe un script trop long sur un gros projet.
03

Le rapport

Une page HTML en A4 portrait (marges 10 mm), couleurs conservées à l'impression. De haut en bas :

Couleur des layers

CouleurType de layer
Vertcontenu : vidéo, image, texte, web
Violeteffets, étalonnage couleur
Orangeaudio
Grislayer désactivé

Ce qui est lu pour chaque layer

  • le type de module ;
  • le début et la fin en timecode, dans la timeline ;
  • le média utilisé (vidéo, image, audio…) ;
  • les paramètres modifiés seulement : les valeurs par défaut courantes (opacité 1, position 0, échelle 1…) sont masquées ;
  • les paramètres animés : la suite de keyframes, timecode : valeur ;
  • les valeurs de liste en clair (loop plutôt que 2).

Pour chaque section : son numéro, son timecode de départ et de fin, sa note, ses tags (TC, CUE, MIDI) et son crossfade (durée et mode de la transition).

Les timecodes sont calculés depuis les beats, au BPM de la piste, avec des images à 25 i/s.
04

Ligne de commande (optionnelle)

Pour interroger Designer depuis une autre machine du réseau, sans ouvrir le plugin. Il faut Python 3.

pip install -r requirements.txt

python run.py --host 192.168.1.100                    # extraction + rapport en une fois
python run.py --host 192.168.1.100 --out mon_show     # écrit mon_show.json + mon_show.html

python extract.py --host 192.168.1.100 --out data.json   # extraction seule
python generate_report.py data.json --out report.html    # rapport seul, depuis le JSON

python test_with_mock.py                              # rapport de démonstration, sans Designer
FichierRôle
run.pyextraction + JSON + rapport HTML, puis un résumé par piste
extract.pyse connecte à Designer (--host, --port, 80 par défaut) et enregistre le JSON
extractor_inner.pyle script envoyé à Designer et exécuté dans son Python 2.7 : à garder à côté de extract.py
generate_report.pyécrit le rapport HTML depuis le JSON ; il s'imprime en PDF depuis n'importe quel navigateur
test_with_mock.pygénère un rapport à partir de données fictives, pour essayer
La ligne de commande lit toute la timeline en un seul appel et produit un rapport à sa propre mise en page, différente de celle du plugin. Pour un gros projet, préférer le plugin (partie 6).
05

Dépannage

SymptômeÀ vérifier
La boîte d'impression ne s'ouvre pasActiver l'Application Mode : Manager › Machine Settings › Enable Application Mode.
Le plugin n'apparaît pasLe dossier doit être <projet>/plugins/timeline-printout-plugin/ avec ses trois fichiers ; relancer le projet.
« Aucune piste trouvée dans le projet »Vérifier qu'une timeline est ouverte dans Designer.
« Réponse vide de Designer »Designer n'a rien renvoyé : relancer Extract ; le message contient la réponse brute pour comprendre.
Extraction trop longueEssayer en décochant Include params : les paramètres ne sont plus lus, seulement modules, temps et médias.
Ligne de commande : « No response from Designer »Vérifier l'adresse (--host), le port (--port, 80 par défaut) et qu'une session est ouverte.
06

À valider

Le plugin a été utilisé dans Designer r32.4. Il reste à vérifier :

  • Les versions de Designer après r32.4.
  • La ligne de commande sur un gros projet : elle lit tout en un seul appel, alors que le plugin est passé à l'extraction piste par piste pour éviter un délai dépassé dans Designer.
  • La liste des valeurs par défaut masquées : un paramètre réglé exactement sur une valeur par défaut courante n'apparaît pas.
  • Les timecodes à 25 i/s : à comparer avec le timecode du projet s'il tourne à une autre cadence.
